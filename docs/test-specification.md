# create-cdn テスト仕様書

## 1. 概要

### 1.1 目的

本文書は、create-cdn パッケージの npm 公開前に実施すべきテストの仕様を定義する。

### 1.2 テスト範囲

- パッケージの基本機能確認
- AWS リソースの作成・設定確認
- エンドツーエンドの動作確認
- エラーハンドリングの確認

### 1.3 前提条件

- 有効な AWS アカウント
- AWS CLI の設定済み（認証情報）
- 検証用ドメイン名の所有
- Route53 ホストゾーンまたは外部 DNS プロバイダーへのアクセス

## 2. テスト環境

### 2.1 必要な環境

```
- Node.js: v18以上
- npm: v8以上
- AWS CDK: v2.130.0以上
- TypeScript: v5.0以上
```

### 2.2 テスト用設定ファイル

```bash
# .env.test
DOMAIN_NAME=test.example.com
ALTERNATIVE_DOMAINS=www.test.example.com,api.test.example.com
CLOUDFRONT_DOMAIN=cdn.test.example.com
NOTIFICATION_EMAIL=test@example.com
CERTIFICATE_ARN_REGIONAL=
CERTIFICATE_ARN_CLOUDFRONT=
```

## 3. テストケース

### 3.1 単体テスト

#### TC-001: パッケージインポートテスト

**目的**: create-cdn パッケージが正しくインポートできることを確認

**手順**:

1. `npm link create-cdn`を実行
2. TypeScript ファイルで以下をテスト:

```typescript
import {
  CertificateStack,
  CloudFrontCertificateStack,
  MonitoringStack,
} from "create-cdn";
```

**期待結果**:

- エラーなくインポート完了
- 型定義が正しく認識される

#### TC-002: スタッククラスのインスタンス化テスト

**目的**: 各スタッククラスが正しくインスタンス化できることを確認

**手順**:

1. CDK アプリケーションを作成
2. 各スタックをインスタンス化
3. `cdk synth`を実行

**期待結果**:

- エラーなく CloudFormation テンプレートが生成される

### 3.2 統合テスト

#### TC-101: ACM 証明書作成テスト（リージョナル）

**目的**: CertificateStack が正しく ACM 証明書を作成することを確認

**手順**:

1. 環境変数を設定
2. `cdk deploy ACM-Certificate-test`を実行
3. AWS Console で ACM 証明書を確認
4. DNS 検証レコードを設定
5. 証明書の検証完了を確認

**期待結果**:

- ACM 証明書が作成される
- DNS 検証が要求される
- 検証完了後、証明書のステータスが「発行済み」になる
- SSM パラメータに証明書 ARN が保存される

#### TC-102: ACM 証明書作成テスト（CloudFront 用）

**目的**: CloudFrontCertificateStack が us-east-1 リージョンで証明書を作成することを確認

**手順**:

1. 環境変数を設定
2. `cdk deploy ACM-CloudFront-Certificate-test`を実行
3. us-east-1 リージョンの ACM で証明書を確認
4. DNS 検証レコードを設定
5. 証明書の検証完了を確認

**期待結果**:

- us-east-1 リージョンに証明書が作成される
- DNS 検証が要求される
- 検証完了後、証明書のステータスが「発行済み」になる
- SSM パラメータに証明書 ARN が保存される

#### TC-103: CloudFront ディストリビューション作成テスト

**目的**: 証明書を使用して CloudFront ディストリビューションが作成できることを確認

**手順**:

1. TC-102 で作成した証明書の ARN を環境変数に設定
2. CloudFront 用の S3 バケットまたはオリジンを準備
3. CloudFront ディストリビューションを作成するスタックをデプロイ
4. ディストリビューションの設定を確認

**期待結果**:

- CloudFront ディストリビューションが作成される
- カスタムドメインが設定される
- HTTPS 接続が有効になる
- 証明書が正しく適用される

#### TC-104: 監視スタックテスト

**目的**: MonitoringStack が正しくアラームを設定することを確認

**手順**:

1. TC-101, TC-102 で作成した証明書情報を設定
2. `cdk deploy ACM-Monitoring-test`を実行
3. CloudWatch アラームを確認
4. SNS トピックとサブスクリプションを確認

**期待結果**:

- 証明書期限切れアラームが作成される（30 日前）
- SNS トピックが作成される
- メール通知が設定される
- Lambda 関数が作成される（チェック用）

### 3.3 エンドツーエンドテスト

#### TC-201: 完全な CDN 構築フロー

**目的**: 実際の使用シナリオで全機能が正しく動作することを確認

**手順**:

1. 新規プロジェクトを作成
2. create-cdn をインストール
3. 全スタックを順次デプロイ
4. CloudFront エンドポイントに HTTPS でアクセス
5. 証明書の詳細を確認

**期待結果**:

- 全リソースが正しく作成される
- HTTPS アクセスが成功する
- 証明書チェーンが正しい
- カスタムドメインでアクセス可能

### 3.4 異常系テスト

#### TC-301: 無効なドメイン名テスト

**目的**: 無効なドメイン名でのエラーハンドリングを確認

**手順**:

1. 存在しないドメイン名を設定
2. スタックのデプロイを試行

**期待結果**:

- 適切なエラーメッセージが表示される
- デプロイが中断される

#### TC-302: 権限不足テスト

**目的**: 必要な権限がない場合の動作を確認

**手順**:

1. 制限された IAM ロールでデプロイを試行

**期待結果**:

- 権限エラーが明確に表示される
- 必要な権限のリストが提示される

### 3.5 パフォーマンステスト

#### TC-401: デプロイ時間測定

**目的**: 各スタックのデプロイ時間を測定

**測定項目**:

- CertificateStack: \_\_\_分
- CloudFrontCertificateStack: \_\_\_分
- MonitoringStack: \_\_\_分

### 3.6 クリーンアップテスト

#### TC-501: リソース削除テスト

**目的**: 全リソースが正しく削除されることを確認

**手順**:

1. `cdk destroy --all`を実行
2. AWS Console で各リソースの削除を確認
3. SSM パラメータの削除を確認
4. CloudWatch ログの確認

**期待結果**:

- 全リソースが削除される
- 残留リソースがない
- 課金が停止する

以下の条件を満たした場合、テスト完了とする：

1. 全テストケースの実施完了
2. 重大な不具合の解消
3. ドキュメントの更新完了
4. サンプルコードの動作確認

## 6. リスクと対策

### 6.1 テスト実施時のリスク

- AWS 利用料金の発生
  - 対策: テスト完了後、速やかにリソースを削除
- DNS 伝播の遅延
  - 対策: 十分な待機時間を設ける
- 証明書検証の失敗
  - 対策: DNS 設定手順書の準備

### 6.2 本番利用時の考慮事項

- 証明書の自動更新設定
- CloudFront のキャッシュ設定
- 監視アラームの閾値調整
