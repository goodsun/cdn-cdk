# CDN CDK プロジェクト作業記録

## プロジェクト概要
- **目的**: AWS CDKを使用した簡単なCDN構築ツールの開発
- **期間**: 2025-07-20
- **進化**: ACM証明書管理ツール → 完全なCDN構築ツール
- **背景**: 既存のACM CDK実装から、実用的なCDN構築ツールへの進化

## 発端となった課題

### ユーザーからの指摘
1. **インフラの押し付け問題**
   - 「Route 53でカスタムドメインを設定などという勝手なことをしないでほしい」
   - 既存ドメイン・既存インフラを持つ企業への配慮不足
   - 「サーバーレスだからといって、すべてAWSでやるべきというのは暴論」

2. **コスト検討の議論**
   - S3へのリバースプロキシ構築の最適解
   - CloudFront vs EC2のコスト比較
   - 転送量による最適な選択の違い

## プロジェクトの進化

### フェーズ1: ACM証明書管理ツール
- **廃止予定コンストラクトの更新**
  - `DnsValidatedCertificate` → `Certificate`に変更
  - 最新のCDK v2ベストプラクティスに準拠

### フェーズ2: CDN構築ツールへの転換
- **create-cdn CLIツールの開発**
  - serverless-cdkを参考にしたシンプルな設計
  - インタラクティブな対話形式でプロジェクト生成
  - テンプレートベースのアプローチ

### フェーズ3: S3静的ウェブサイトホスティング対応
- **7つのオリジンタイプのサポート**
  1. `s3-new`: 新規S3バケット（OAC経由・推奨）
  2. `s3-website-new`: 新規S3バケット（静的ウェブサイトホスティング）
  3. `s3-website-existing`: 既存のS3静的ウェブサイト
  4. `s3-existing`: 既存のS3バケット（OAC経由）
  5. `http`: 既存のWebサイト（HTTP/HTTPS）
  6. `alb`: Application Load Balancer
  7. `apigateway`: API Gateway

## 実施した主要機能

### 1. CLIツール (create-cdn)
- **簡単なプロジェクト作成**
  ```bash
  npx create-cdn my-website
  ```
- **対話的な設定収集**
  - ドメイン名、オリジンタイプ、監視設定など
  - .envファイルによる設定管理

### 2. CloudFront統合
- **高速なCDN配信**
  - 世界中のエッジロケーションからの配信
  - 自動的なHTTPS化
  - キャッシュ最適化

### 3. S3静的ウェブサイト完全対応
- **OACとウェブサイトホスティングの選択**
  - セキュアなOAC経由アクセス（推奨）
  - 公開ウェブサイトホスティング
  - 既存S3ウェブサイトの利用

### 4. DNS設定支援
- **デプロイ後の出力改善**
  - DNS設定手順の明確な表示
  - サブドメインとCloudFrontドメインの出力
  - コピー&ペースト可能な形式

## 重要な学び

### 1. ツールの進化
- **単機能から統合ツールへ**: ACM証明書管理だけでなく、完全なCDN構築ツールに
- **ユーザー視点の重要性**: 「一般人にも使える」ツールを目指す

### 2. S3ウェブサイトホスティングの技術的考慮
- **プロトコルの違い**: S3ウェブサイトエンドポイントはHTTP_ONLYが必要
- **オリジンの選択**: OAC（セキュア）vs ウェブサイトホスティング（公開）

### 3. クロスリージョン参照の課題
- **CloudFront証明書**: us-east-1に必須
- **MonitoringStack**: 別スタックとして作成が必要
- **解決策**: crossRegionReferences: true の設定

### 4. 既存リソースの活用
- **ワイルドカード証明書**: *.example.comなど既存証明書の再利用
- **ARNによるインポート**: 新規作成より既存利用を優先

### 5. ACMの自動更新について
- **誤解**: 「証明書の期限を監視する必要がある」
- **正解**: 「DNSレコードが維持されているか監視する」
- ACM自体は自動更新されるが、外部要因（DNS）の監視が必要

### 既存環境の尊重
- 企業は数十年の運用実績がある
- 新技術の押し付けは避ける
- 選択肢を提供することが重要
